PLSB Algorithm

Predictive Lexeme Spill Buffering capacity estimation pipeline

Production Rule: Combined
1. Detect Boundary Spill

A lexeme exceeds the available input buffer space B. The L bytes already scanned are copied to the spill buffer.

2. Estimate Capacity

Three signals are evaluated: P75 (Q), EWMA (E), and context-conditioned EWMA (M). The maximum becomes C_raw.

3. Apply Safety Bound

The final capacity C is clamped to the range [16, 4096] and must exceed the scanned length L + 1.

4. Allocate and Continue

The spill buffer is allocated at exactly C bytes. The lexer resumes scanning without reallocation cascade.

Combined Capacity Formula

Step 1 — Estimate initial capacity:
  Q = P75(class)                           // 75th-percentile of historical class lengths
  E = ceil(EWMA(class))                    // Exponential moving average (alpha = 0.20)
  M = ceil(cond_EWMA[prev_class -> class]) // Context-conditioned transition length

Step 2 — Combine the estimates:
  C_raw = max(Q, E, M)

Step 3 — Apply safety bound:
  C = clamp(max(C_raw, L_scanned + 1), 16, 4096)
Q — P75 Length Robust

75th percentile of historical lexeme lengths for the current syntactic class. Filters short-token noise; handles typical long lexemes.

E — EWMA Length Adaptive

Exponentially weighted moving average of recent lexeme lengths (alpha = 0.20). Adapts quickly to local bursts of long identifiers or comments.

M — Context Length Transition

EWMA conditioned on the prior syntactic class transition (e.g. typedef → identifier). Captures cross-class length patterns.

L + 1 — Safety Floor Invariant

Guarantees the allocated capacity strictly exceeds the bytes already scanned before the boundary reload. Prevents immediate re-spill.

About This Project

Predictive Lexeme Spill Buffering (PLSB) compiler research project. This system demonstrates the lexical scanning pipeline with streaming two-buffer input, online empirical token length estimation, and dynamic heap spill buffer pre-allocation.

What Is Lexical Analysis?

Lexical analysis is the initial phase of a compiler. It reads the source code character by character and converts it into a continuous stream of tokens — the smallest meaningful syntactic units of a program (keywords, identifiers, literals, operators).

What Is Two-Buffer Input?

Reading characters individually from disk is inefficient. Compilers use two fixed-size buffers of size $B$. The scanner inspects characters in the active buffer while the companion buffer is refilled asynchronously.

What Is Token Frequency?

Token frequency analysis counts occurrences of each token category and lexeme across source code. This reveals code distribution characteristics, keyword usage density, and statistical patterns in software repositories.

How PLSB Predicts Buffer Capacity

When an uncompleted token crosses a buffer boundary, standard lexers allocate a fixed minimum buffer and repeatedly double it, triggering costly copy cascades. PLSB uses historical class percentiles (P75), moving averages (EWMA), and context transitions to pre-size the heap spill buffer accurately in one allocation. 

Capacity C = clamp(max(P75, EWMA, cond_EWMA, L_scanned + 1), 16, 4096)
